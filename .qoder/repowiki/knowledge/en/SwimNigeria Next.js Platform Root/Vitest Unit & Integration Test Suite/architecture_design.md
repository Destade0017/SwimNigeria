Tests live under `src/__tests__/` and are organized as one `.test.ts(x)` file per source unit: component tests (e.g. `button.test.tsx`, `card.test.tsx`, `dialog.test.tsx`) use `@testing-library/react` with `render`/`screen`/`fireEvent`; server-side route handler tests (e.g. `auth-callback.test.ts`, `supabase-redirect.test.ts`) import Next.js Route Handlers via dynamic `await import('@/app/...')` and construct `new Request(...)` to exercise GET/POST logic; Supabase client/environment tests (`supabase-clients.test.ts`, `supabase-env.test.ts`, `supabase-proxy.test.ts`, `supabase-redirect.test.ts`) mock `@supabase/ssr` and `next/headers` via `vi.mock`. A shared `setup.ts` bootstraps the jsdom environment by polyfilling `HTMLDialogElement.prototype.showModal/close` and importing `@testing-library/jest-dom/vitest` matchers. Tests target both React components in `@/components/ui/*` and runtime modules in `@/lib/supabase/*` and `@/app/auth/callback/route`, keeping UI rendering separate from server-side request/response assertions.
