The module is organized into four concerns:
- `supabase/` — environment and client layer built on `@supabase/ssr`. `env.ts` centralizes `NEXT_PUBLIC_SUPABASE_URL` / `ANON_KEY` validation (throwing a custom `SupabaseConfigurationError`) and trusted-origin resolution; `client.ts` exposes a browser factory via `createBrowserClient`; `server.ts` wraps `createServerClient` with a Next.js `next/headers` cookie adapter that tolerates RSC read-only cookie stores by catching `ReadonlyRequestCookiesError`; `proxy.ts` implements request-interception session refresh (`updateSession`) using a fast-path bypass for anonymous requests; `redirect.ts` provides `sanitizeRedirectUrl`, an open-redirect defense that enforces same-origin relative paths.
- `validation/auth.ts` — Zod schemas (`registerSchema`, `loginSchema`, `forgotPasswordSchema`, `resetPasswordSchema`) used by both Server Actions and client-side forms, each paired with an inferred `*Input` type and a `*FieldErrors` record.
- `constants.ts` — frozen app identity (`APP_CONFIG as const`) and brand palette (`BRAND_COLORS as const`).
- `utils.ts` — zero-dependency `cn()` CSS class combiner.
- `articles.ts` and `courses.ts` — strongly typed, in-memory content registries (`ARTICLES_DATA`, `COURSES_DATA`) exposing public query helpers (`getPublishedArticles`, `getArticleBySlug`, `getCategories`, plus course syllabus/preview helpers) that filter out unpublished entities at every nesting level (course → module → lesson).

Dependency direction is one-way: `supabase/*` modules depend only on env vars and `@supabase/ssr`; `validation/auth.ts` depends only on `zod`; `articles.ts`/`courses.ts` are pure data + query functions with no runtime dependencies beyond TypeScript types. The top-level files (`articles.ts`, `courses.ts`, `constants.ts`, `utils.ts`) have no intra-module imports, making them leaf utilities consumed by pages and route handlers.
