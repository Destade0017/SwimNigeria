All three child page groups (marketing_pages, content_pages, auth_pages) are mounted as sibling route segments under src/app/ and share two parent artifacts: `layout.tsx` (the root layout providing Supabase client context, metadata, and common chrome) and `globals.css` (global styles). Routing is purely file-system based — static routes like `about/page.tsx`, dynamic routes like `articles/[slug]/page.tsx` and `courses/[courseSlug]/lessons/[lessonSlug]/page.tsx`, and an API-style `auth/callback/route.ts` for the Supabase PKCE callback. Cross-child communication is minimal; children consume data through the shared `@/lib` server loaders rather than talking to each other directly.
